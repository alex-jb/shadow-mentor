# Shadow → Flow presentation mapping

Machine-readable twin: `shadow-flow-presentation-mapping.json` (generated by
`scripts/gen-flow-presentation-package.mjs`, verified byte-identical by
`test/shadow-flow-presentation-spike.test.js`).

## Boundary (restated because it is the whole point)

**Shadow analyzes and attests. Flow visualizes. XREAL displays.** Every status, stance, verdict,
first-failure localization, and verification result in this mapping is a literal copy from Shadow
fixtures (`banking-narrative.mjs` + `audit-chain.guided-story.json`). Flow must never recompute or
soften any of them. A test pins this (statuses byte-equal to the fixture scenario).

## Canonical case

- Case: `case-2026-Q3-0042` — MID-MARKET LOAN, CASE #SL-2026-014, $8.4M REQUEST
- Narrative chain preserved: CASE → COUNCIL → FIRST FAILURE → EVIDENCE LINEAGE → DOWNSTREAM IMPACT
  → HUMAN REVIEW → APPROVAL → VERIFICATION
- Presented scenario: `tamper_seq_3` (hero beat); `pristine` carried for the storyboard's clean open.
- Honesty labels carried on every row/node: `mode_label: FIXTURE MODEL`,
  `network_used: false`, `physical_device_validated: false`.

## Spatial narrative (presentation groups)

| Group | Contents | Why there |
|---|---|---|
| `center` | `banking-v1:n3:claim` — **FIRST FAILURE / 首个失败** | The spatial focal point; identifiable immediately |
| `left-case` | Case card + evidence items B0L0/B0L1/B0L2 | Case and source evidence to the left |
| `ring-council` | 5 council voices with stance + confidence | Attributable roles around the center |
| `right-downstream` | Decision (REVIEW, dissent 3/5) → Human Review → Approval | Consequences and the human path to the right; review ≠ approval |

| `verification-area` | HASH_CHAIN / RECORD_INTEGRITY / DIGITAL_SIGNATURE / ANALYTICAL_CORRECTNESS + attestation status + device boundary | Verification kept separate from the business conclusion |

## Node fields (every element)

`id` (stable) · `type` · `label_en` · `label_zh` · `status` · `status_family`
(pass/fail/warn/neutral/abstain/info, from the shared vocabulary's severity) · `group` ·
`source_ref` (repo-relative provenance) · `refs.first_failure_ref` · `refs.human_review_ref` ·
`refs.approval_ref` · `refs.verification_ref` · lineage nodes add `sequence`,
`status_by_scenario`, `refs.is_first_failure`, `refs.is_affected_downstream`.

## Semantic guarantees (tested)

1. First Failure is the only `center` node, status `FIRST_FAILURE`.
2. Downstream nodes carry `AFFECTED_DOWNSTREAM` — frozen as consequence, never independently
   re-judged (vocabulary a11y text says exactly this, in both languages).
3. Human Review (`REQUIRES_HUMAN_REVIEW`) and Approval (`NOT_PRESENT` — the fixture grants none)
   are distinct nodes with distinct statuses.
4. `ANALYTICAL_CORRECTNESS: NOT_EVALUATED` is rendered in the verification area — a fully green
   chain never claims the decision was *correct* (FORBIDDEN_MAPPINGS honored).
5. Bilingual labels come from the shared vocabulary where the concept exists there; fixture-only
   strings (voice names, stances) get presentation-local zh strings in the builder.
6. All statuses byte-match the fixture scenarios; no dangling references; deterministic output.

## What this mapping does NOT do

- Does not create a new row schema (reuses `shadow-flow-export/1.0`).
- Does not recompute or re-weight any council conclusion.
- Does not claim native Shadow Lens progress, MyGlasses handoff resolution, or any on-device result.
- Does not touch the live Flow service; the package is operator-local and offline.
