# Decision Web Integration Handoff

Status: Core side COMPLETE for Web consumption; **no Web change ships in this
increment.** This document is the contract Shadow Web builds against in its
own bounded, separately approved increment. It refines the discovery-level
DECISION_WEB_HANDOFF.md with the implemented specifics.

## What Core now guarantees to Web

- 1.2 packages import through the existing package-import path: same member
  transport, same manifest signature, same closed failure discipline. A 1.2
  package with any decision failure verifies as `FAILED` — Web will never see
  a "verified package, broken decision" split.
- The decision member is plain hash-bound JSON at
  `decision/decision-amendment.json` with closed vocabularies
  (DECISION_AMENDMENT_CONTRACT.md). All text fields are NFC, size-bounded,
  control-character-free — safe for React-text-node rendering with no
  sanitizer (the existing Web posture).
- The chain layer is unchanged for 1.0/1.1; 1.2 packages link exactly like
  1.1 (`shadow-package-supersession/1`), marker `DECISION_AMENDMENT`.
- The lifecycle is a pure function Web can port with parity tests, exactly
  like it ported `verifyPackageDir` and `verifyChainEntries`:
  `deriveDecisionLifecycle` (+ `packageDecisionState`, `transitionError`) in
  `lib/decision-amendment.mjs`, golden-testable against
  `verify-chain --json` output (`decision_lifecycle` field).

## Web display requirements (when the Web increment is approved)

- New FIFTH disjoint vocabulary: the lifecycle states. Never merged into
  package failure codes, web verification states, chain node states, or
  semantic statuses.
- Per decision node: decision type, actor display name + `actor_id`, role,
  and — verbatim, equal visual weight, no checkmark iconography —
  `DECISION_IDENTITY_DECLARED_NOT_VERIFIED` and
  `DECISION_AUTHORITY_UNVERIFIED`. `FIXTURE_DECISION_ONLY` renders on every
  decision like `VERIFIED_FIXTURE_KEY` renders today (never collapsed into a
  generic success).
- Existing semantic statuses map: `HUMAN_REVIEW_RECORDED` may be driven by a
  signed review member (NO_CHANGE); `APPROVAL_PRESENT` by a signed approval —
  stamp color rule unchanged (info blue, never verification green).
- Predecessors and superseded dispositions stay permanently visible; the
  effective-decision indicator moves, history never disappears.
- Forks/conflicts: render every branch + `DECISION_CONFLICT`; no selection
  affordance; no tiebreak. Effective decision shows "none derivable".
- Every lifecycle statement carries `DERIVED_FROM_LOCAL_SET` phrasing beside
  the existing three chain disclosures.

## What Web MAY build before any signing exists (workflow Option B)

- Local drafting of a `shadow-decision-intent/1` file, labeled
  `UNSIGNED DRAFT`, structure-validated client-side, previewed distinctly
  from signed artifacts, exportable for the Core CLI, discardable. Drafts
  never enter the timeline, never receive lifecycle chips, and are never
  displayed as reviewed/approved/rejected/effective.

## What Web MUST NOT do (unchanged invariants)

Sign anything (no browser keys, PEM private-key blocks stay rejected); mutate
imported packages; infer authorization; auto-resolve forks; collapse the
integrity / identity / authority / lifecycle axes into one badge; imply that
a draft or an unsigned intent has any evidentiary status.

## Exact next Web action (for the future Web increment's task brief)

Extend the Web package verifier parity port to 1.2 (decision member checks +
version-bound marker), port `deriveDecisionLifecycle` with golden parity
fixtures generated by `verify-chain --json` over the committed fixture arc
(DECISION_FIXTURE_RUNBOOK.md), and add the decision timeline node type with
the display rules above — read-only, no drafting in the first Web increment.
