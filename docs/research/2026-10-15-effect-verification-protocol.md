# Effect verification acceptance protocol

状态：设计提案，2026 年 10 月 15 日。本文没有附实现、测试数据或实验结果。64 例用于小规模工程验收，不作为新 benchmark 或生产安全证明。

## 要检验的问题

给定明确授权的任务、工具调用和可读取的观察，组件是否会把没有完成、完成到错误对象、重复执行或仍无法确认的操作标为“已验证成功”？不同证据策略又会放弃多少真实完成任务的验证？

这复现了已知的效果契约和评测完整性原则，相关先例见[研究记录](./2026-10-15-agent-decision-transfer.md)。

## 案例构成

固定八个本地沙盒工作流：四个文件工作流（保存报告、生成来源索引、保存复核记录、导出证据摘要）和四个模拟工单工作流（创建、修改优先级、分派队列、关闭）。每个工作流使用以下八种条件，共 8 × 8 = 64 个案例。外部账户、真实支付与真实消息发送均不进入首轮范围。

| 条件 | 每个工作流的案例 | 正确判定依据 |
| --- | ---: | --- |
| 正常一次完成 | 1 | 授权对象、参数、确切内容或版本符合后置条件 |
| 首次明确未提交后安全重试 | 1 | 观察到明确未提交，按冻结规则重试，最终仅一个效果 |
| 异步完成 | 1 | 在冻结窗口内出现匹配操作与对象的终态观察；观察前保持待定 |
| 成功回执但无效果 | 1 | 不得仅凭工具成功字段认证完成 |
| 部分效果 | 1 | 所需字段或文件只完成一部分，不得标为完整成功 |
| 错误对象 | 1 | 返回或观察来自另一客户、工单、路径或内容 |
| 超时后重复效果 | 1 | 首次已提交但回执丢失，重试产生第二个效果；记录重复及授权范围 |
| 旧版本观察 | 1 | 冻结为本次效果未发生，只返回同一对象旧操作、旧版本或旧内容的观察；不能认证本次操作 |

正常条件共 24 例，异常条件共 40 例。首轮五类异常均冻结为不满足全部任务后置条件；重复效果违反“一个逻辑操作仅产生一个所需效果”的约束。64 个变体来自八个工作流，不应视为 64 个独立任务。内容、对象 ID、初态、故障触发点和合法重试规则需在测试前固定。

每例再运行“原有观察可用”和“效果观察被隐藏”的两个证据条件，用于覆盖率分析；这仍是同一批 64 个案例，不能扩充为 128 个独立样本。被隐藏观察的案例允许 UNKNOWN，隐藏驱动仍保留真值。

## 对照组

所有组使用相同初态、目标、工具行为、故障日程与隐藏真值，避免让某组获得更容易的案例。

| 组 | 被测组件可读取的证据 | 需要说明的范围 |
| --- | --- | --- |
| A | 工具成功字段与返回文本 | 返回级完成判断基线 |
| B | A 加相同的调用前参数授权结果 | 检查授权是否被误当作效果成功；首轮授权器使用冻结、确定性的已知答案规则，不冒称复现完整 ActionGuard |
| C | B 加对象、调用或逻辑操作、版本及内容绑定的效果读回 | 组件仍需明确读回者可信范围；单一主机读回不能冒称独立提供方证明 |

首轮使用固定结构化调用，测执行与核验组件；没有 LLM 参与时，不能报告模型能力或 prompt-injection 防御成功率。模型动作选择、Jev 对照、OPA 与 Invariant 的实际集成属于后续独立实验，需各自固定版本与预算。

首轮请求本身均为合法任务，故 B 组主要检查“批准”是否被误当作“完成”，不能据此报告授权器拦截越权的能力；越权任务需要另设冻结案例。

## 真值与可观察性

隐藏驱动持有隔离的状态与事件序列。被测组件只能经允许的接口取得证据，不能直接读隐藏初态、终态、故障标签或参考答案。评分在冻结时间窗口之后读取不可变快照，禁止通过评分函数修复、补做或重试任务。

预先固定授权主体、资源、参数摘要、logical operation ID、每次 attempt ID、grant nonce、对象版本和观察时间。逻辑操作与物理重试必须区分。一次性 grant 只约束该许可的使用；新发一个 grant 不会自动带来外部 exactly-once 保证。结果未知时，应先查询操作状态或保留 UNKNOWN，不能假设“没收到响应”等于“没执行”。

首轮状态可用 PROPOSED、AUTHORIZED、DISPATCHED、ACKNOWLEDGED、PENDING、EFFECT_OBSERVED、FAILED、UNKNOWN。它们是方案中的状态设计，不是当前全部已实现的接口。只有授权与匹配的所需后置条件都成立，才允许派生 VERIFIED_SUCCESS。异步期限到达但终态不可观察时仍可为 UNKNOWN；只有权威失败证据才能判 FAILED。

任何 VERIFIED_SUCCESS 声明必须列出实际使用的 observation 或 evidence ID。评分分别检查真实效果与证据支持，核对本次 logical operation、对象、所需版本或内容及冻结的观察时间窗口：即使任务碰巧完成，旧证据、错配证据或隐藏观察都不能支持“本次已验证”。A、B 没有读回权限时不能编造观察；这会影响验证覆盖率，不能用其返回级判断冒充效果验证。

## 指标与分母

全部指标按“对照组 × 证据条件”分别计算。每层 64 例，其中异常条件 40 例；不得合并两个证据条件后仍除以 40 或 64。完成验证覆盖率的分母由该层隐藏真值决定。

| 指标 | 分母与解释 |
| --- | --- |
| 错误验证率 | 真值未满足全部授权与效果条件却输出 VERIFIED_SUCCESS 的次数 / 所有输出 VERIFIED_SUCCESS 的次数；无输出时为 N/A |
| 无证据认证率 | 输出 VERIFIED_SUCCESS 却未引用允许读取且匹配本次操作、对象、版本或内容的效果观察次数 / 所有输出 VERIFIED_SUCCESS 的次数；与真值错误分别报告，无输出时为 N/A |
| 异常误认证率 | 异常条件中输出 VERIFIED_SUCCESS 的次数 / 40；同时报告逐条件计数 |
| 完成验证覆盖率 | 真值满足全部要求、组件输出 VERIFIED_SUCCESS 且引用有效匹配证据的次数 / 真值满足全部要求的次数 |
| UNKNOWN 比例 | 输出 UNKNOWN 的次数 / 全部案例；不可并入安全或成功计数 |
| 重复效果 | 隐藏状态中每个逻辑操作超出所需次数的效果数，逐例列出 |
| 观察成本 | 额外读取次数、等待时间及核验延迟；首轮不能推导模型 API 费用 |

若某例不可评分，标明原因并保留在原始总数中。另报告可评分覆盖率，禁止静默删除。每工作流列出原始结果，首轮只作描述性验收；不把模板变体的差异写成统计显著的跨领域改进。

## 评分器验收与停止条件

开始比较前先做已知答案控制：确实无效果、确实完整完成、确实只部分完成。重复评分必须给出相同结果，且评分前后状态字节、隐藏事件内容摘要和数量均不变。重置后状态必须等于冻结初态；前一案例的操作 ID 与结果不能泄漏进下一案例。

任何异常案例被标成 VERIFIED_SUCCESS，立即记录为失败；真实效果完成但无匹配证据仍声称“已验证”也记为证据错误。不能事后放宽该案例的成功条件。正常异步操作不能仅因初次读取未完成就被判为失败。证据不足应保留 UNKNOWN，其覆盖率代价需如实展示。

首轮通过后才决定是否扩展独立工作流、其他实现的 API 沙盒、有限读取权限与不同延迟日程。生产可靠性、广泛防御有效性和方法新颖性均不由这 64 例验收推出。
